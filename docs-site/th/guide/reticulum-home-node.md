# Home node — Reticulum / LXMF (โหนดบ้าน)

ฟีเจอร์ **Home node** ให้ Mac หรือ Raspberry Pi บน Wi‑Fi เดียวกันเป็นทางส่งข้อความแชต 1:1 ที่ **เข้ารหัสแล้ว (sealed)** ผ่านเครือข่าย **Reticulum** ด้วยข้อความแบบ **LXMF**

ในแอปเรียกว่า **Settings → Home node**  
ค่าเริ่มต้น = **ปิด** — เปิดเฉพาะเมื่อมีโปรแกรม bridge รันบน Mac/Pi จริง

---

## สรุปสั้นๆ ว่าคืออะไร

| คำ | ความหมายใน ResilNet |
|----|---------------------|
| **Reticulum (RNS)** | เครือข่าย overlay สำหรับส่งแพ็กเก็ตแบบกระจาย (มักรันบนคอมพิวเตอร์ ไม่ใช่บน Heltec LoRa) |
| **LXMF** | รูปแบบข้อความบน Reticulum (คล้าย “จดหมาย” ใน mesh ของ RNS) |
| **Home node / bridge** | โปรแกรมบน Mac/Pi ที่รับ sealed bytes จากแอปผ่าน HTTP แล้วห่อส่งต่อด้วย LXMF |
| **ที่อยู่โหนด (destination)** | รหัสยาว ~32 ตัวอักษรของโหนด LXMF — ใช้ผูกกับเพื่อนในแอป |

```text
มือถือ A (ResilNet)          Mac/Pi “บ้าน” A              Mac/Pi “บ้าน” B          มือถือ B
   │  HTTP (LAN)                │  LXMF บน Reticulum           │  HTTP (LAN)              │
   │  ส่งซอง E2EE ─────────────►│ ────────────────────────────►│◄──────────────── รับซอง │
   │  (ถอดรหัสไม่ได้บน bridge)   │                              │                          │
```

### สิ่งที่ Home node **ทำ**

- เป็นทางส่งเสริมเมื่อมือถือกับ Mac/Pi อยู่ LAN เดียวกัน
- ส่งต่อเฉพาะ **ซองที่เข้ารหัสแล้ว** — bridge **ถอดข้อความไม่ได้**
- ช่วย store-and-forward ระหว่างโหนด Reticulum (เมื่อตั้งลิงก์ RNS ระหว่าง Mac/Pi ไว้)

### สิ่งที่ Home node **ไม่ใช่**

- **ไม่แทนที่** การเข้ารหัสปลายทางถึงปลายทางของ ResilNet
- **ไม่ใช่** LoRa / ไม่ใส่ LXMF เต็มรูปบน Heltec (เพย์โหลดวิทยุเล็กเกินไป — ดู lab overhead)
- **ไม่ใช่** Local Wi‑Fi แบบโทรศัพท์↔โทรศัพท์ (UDP ในแอป) — คนละชั้น
- **ไม่ใช่** กระดาน #mesh / Area bulletin ในเวอร์ชันนี้
- **ไม่บังคับ** สำหรับใช้งานปกติ — BLE / Nostr / ESP32 ยังทำงานโดยไม่เปิด Home node

## เปรียบเทียบช่องทาง (ผู้ใช้)

| ช่องทาง | อุปกรณ์ | เมื่อไหร่เหมาะ | E2EE แชต 1:1 |
|---------|---------|----------------|--------------|
| Bluetooth mesh | มือถือใกล้กัน | ออฟไลน์ระยะใกล้ | ใช่ |
| Local Wi‑Fi | มือถือใน LAN/ฮอตสปอตเดียวกัน | LAN เร็ว มือถือ↔มือถือ | ใช่ |
| ESP32 / LoRa | บอร์ด ResilNet | ออฟไลน์ระยะกลาง | ใช่ (opaque) |
| Nostr | อินเทอร์เน็ต | ไกล / คนไม่ได้อยู่ LAN เดียวกัน | ใช่ |
| **Home node (LXMF)** | มือถือ + Mac/Pi | มีโหนดบ้านบน Wi‑Fi / ต้องการ relay ผ่าน RNS | ใช่ (opaque บน bridge) |

ลำดับที่มักสมเหตุสมผลเมื่อหลายทางพร้อม: Local Wi‑Fi (ถ้าเปิดเซสชัน) → Nostr (ถ้ามีเน็ต) → Home node (ถ้าเปิดและเพื่อนผูกที่อยู่แล้ว) → BLE / LoRa ตามสถานการณ์

## สิ่งที่ต้องมีก่อนใช้งาน

### ฝั่ง Mac หรือ Raspberry Pi

1. เครื่องอยู่ใน **Wi‑Fi เดียวกับมือถือ** (หรือเข้าถึง IP ของโหนดได้)
2. ติดตั้งและรัน **bridge + Reticulum** จาก lab ใน repo:  
   `labs/reticulum_lxmf/`  
   (venv, `rnsd`, คำสั่ง `bridge listen` — รายละเอียดใน `labs/reticulum_lxmf/README.md`)
3. HTTP ของ bridge ฟังพอร์ต เช่น **8765 / 8766** (ตัวอย่างใน lab)
4. จำ **IP ของ Mac/Pi** ใน LAN เช่น `192.168.1.10`

> Lab นี้พิสูจน์แนวทางและ API — ผู้ดูแลโหนดต้องรัน bridge เอง แอปมือถือไม่ได้ติดตั้ง Reticulum ลงในโทรศัพท์ในเวอร์ชันนี้

### ฝั่งมือถือ (ResilNet **1.9.64+**)

1. มีเพื่อนในรายชื่อที่คุย 1:1 ได้แล้ว (แลกคีย์ / QR ตามปกติ)
2. เปิด **Settings → Home node**
3. ใสที่อยู่โหนด เช่น `192.168.1.10:8766` หรือ `http://192.168.1.10:8766`
4. กดตรวจการเชื่อมต่อ / บันทึก — สถานะควรเป็นออนไลน์และแสดงที่อยู่โหนด
5. เปิดสวิตช์ **ใช้โหนดบ้าน** เมื่อพร้อม
6. **ผูกเพื่อน** — วางที่อยู่โหนดของเพื่อน (รหัสจากหน้า Home node ของเขา) ทีละคน

## ขั้นตอนในแอป (ละเอียด)

### 1) เปิดแผ่น Home node

**Settings → Home node** (หรือข้อความเทียบเท่าตามภาษา UI)

จะเห็น:

- ที่อยู่โหนด (IP:พอร์ต)
- ปุ่มตรวจการเชื่อมต่อ
- ที่อยู่ของโหนดนี้ (คัดลอกให้เพื่อน)
- รายชื่อเพื่อนที่ผูกแล้ว
- ปุ่มผูกเพื่อน

### 2) ใส่ที่อยู่และตรวจ

1. กรอก IP หรือ URL ของ Mac/Pi ที่รัน bridge  
   ตัวอย่าง: `192.168.1.10:8766`
2. บันทึกและรีเฟรชสถานะ
3. ถ้าออฟไลน์: ตรวจว่า bridge รันอยู่, มือถือกับ Mac อยู่เน็ตเดียวกัน, ไฟร์วอลล์ไม่บล็อกพอร์ต

### 3) แชร์ที่อยู่โหนดของคุณ

1. คัดลอก **ที่อยู่โหนดนี้** จากหน้าจอ
2. ส่งให้เพื่อนผ่านช่องทางที่ไว้ใจได้ (หรือให้เขาเห็นบนหน้าจอคุณ)
3. เพื่อนนำไปวางใน “ผูกเพื่อน” ฝั่งเขา (และคุณผูกของเขากลับ)

การผูก = บอกแอปว่า “เพื่อนคนนี้ส่งผ่าน LXMF ไปที่ปลายทางนี้ได้”  
**ไม่ใช่** การแลกคีย์เข้ารหัสใหม่ — คีย์ E2EE ยังเป็นของ ResilNet ตามเดิม

### 4) ส่งแชต

1. เปิดแชต 1:1 ตามปกติ
2. เมื่อ Home node เปิด + ถึงโหนดได้ + มีการผูกเพื่อน แอปจะ **พยายามใช้ทางนี้แบบ opportunistic** (ส่งซองที่ seal แล้ว)
3. อินบ็อกซ์ฝั่ง bridge ถูกดึงเป็นระยะเมื่อฟีเจอร์เปิด

ไม่ต้องเลือก “โหมด Reticulum” แยกในแชตทุกครั้ง — ทำงานคู่กับ router / ทางอื่นของแอป

## ผู้ดูแลโหนด (Mac/Pi) — ภาพรวม

รายละเอียดคำสั่งอยู่ใน `labs/reticulum_lxmf/README.md` สรุปบทบาท:

| ส่วน | หน้าที่ |
|------|---------|
| `rnsd` | เดมอน Reticulum (อินเทอร์เฟซ TCP ฯลฯ) |
| `bridge listen` | ต่อ LXMF + HTTP `/status` `/send` `/inbox` `/announce` |
| `identity_map` | แผนที่ peerId ของ ResilNet ↔ ที่อยู่ LXMF (ใน lab / โหนด) |
| บล็อบ **RNLB** | ห่อ sealed bytes ของ ResilNet ในเนื้อ LXMF |

หลักการสำคัญ: เนื้อหาที่ bridge เห็นคือ **opaque** — มี magic `RNLB` + peer id + sealed payload ไม่มี plaintext แชต

> อยากให้ **โหนดพกพา 2 เครื่องคุยกันเองด้วย LoRa** (ไม่พึ่งเน็ต)? ดู
> `labs/reticulum_lxmf/docs/pi_rnode_mesh.md` — ตั้ง Pi + RNode ฝั่งละตัว
> ให้พารามิเตอร์วิทยุตรงกัน แล้วมือถือคุยกับ Pi ข้างตัวผ่าน HTTP เหมือนเดิม
> (คนละ stack กับ ESP32/Heltec LoRa 230B ของ ResilNet)

## ข้อจำกัดและความปลอดภัย

- Bridge บน LAN เห็น metadata บางอย่าง (ใครส่งเมื่อไหร่, ขนาด) แต่ไม่ควรเห็นข้อความถ้า E2EE ถูกต้อง
- ผูกที่อยู่ผิดคน = ส่งซองไปคนผิด (เขาถอดไม่ได้ถ้าไม่มีคีย์ แต่ของหาย/ผิดที่)
- อย่าเปิดพอร์ต bridge สู่สาธารณะอินเทอร์เน็ตโดยไม่มีการป้องกัน
- Heltec / LoRa ของ ResilNet **ไม่** รับสแต็ก LXMF เต็ม — อย่าคาดหวังว่าวิทยุ LoRa = Reticulum
- ฟีเจอร์นี้ยังเป็นทางเลือก; บางส่วนของ router ฝั่ง Rust (`TransportType::LxmfBridge`) อาจยังไม่ครบเท่า HTTP ฝั่งแอป — พฤติกรรมหลักที่ผู้ใช้เห็นคือ Settings + ส่ง/ดึงผ่าน bridge
